# 尺码建议设计

本文件说明尺码建议的证据口径、模型、验证与上线后的对账方式。业务操作见 `docs/业务约定.md`。

## 证据口径

四类记录按真实含义使用，互不替代：

- **试穿**（fittings）：某时刻某品牌某尺码的直接结果（small/fit/large/unknown），是最直接的本人证据；unknown 不推断方向。
- **购买**（orders）：只说明买了什么，不说明合不合身。
- **换退**（aftercare return/exchange）：尺码原因（size_small/size_large）给出方向；换货新单尺码记为"解决尺码"，但未经回访确认；非尺码原因（fabric、changed_mind 等）不作合身证据。
- **回访**（aftercare followup/fit）：唯一的合身确认。

未回访、未退货、未售出都不是确认标签。售后更正（correct）改变后续评估与当前建议资格，但历史建议记录保持写入时的内容，仍按当时证据解释。

## 建议的给出

`advisor.recommend` 先只用证据得出合身结论，再独立附上当前可买清单：

- 库存不参与合身判断；合适尺码售罄时 `fit_in_stock=false`，可买清单另列并注明"仅为库存信息，不代表同等合适"。
- 证据不足时拒答（abstain），不给确定尺码，也不把下一码说成同等合适。
- 建议只记录，不创建订单；下单仍是独立业务操作，可用 `advice` 字段关联。
- 每条建议记录模型版本、关键依据、适用人群与不确定处，持久化且不可改。

线上策略 `combined-1`：本人确认购买 > 本人最近有效试穿 > 本人换货解决 > 本人退货方向，都没有时回退到人群统计（同品牌已验证人群，体型相近者优先，样本不足或意见分散则拒答）。

## 可比较验证

`scripts/evaluate_advisor.py` 对候选模型（own-history / crowd-neighbors / combined）做同口径验证：

- **时间诚实**：每个请求只用它发生时刻（含）之前可观察的记录；售后更正按业务时间（corrected_at）生效，不用后来的售后回答较早的请求。
- **分组诚实**：同一人的全部请求落在同一验证折，连买换货不拆到两侧；各折按首单时间连续划分，所有模型面对同一折划分。
- **指标可见**：可靠性只在已验证答案上计算；只知方向的退货单列；无法验证的回答保持可见但不计入可靠性。报告按体型、品牌、证据积累（新款）分层，缺口直接可读。

合成历史（`data/history.json`）的生成参数不含真实规律，报告数字只用于比较模型口径与检查缺口，不代表真实经营效果。

## 上线后的对账

`advisor.review` 把每条建议、关联订单与当前售后（含更正）对照：confirmed（验证尺码与建议一致）、contradicted（建议尺码被尺码类售后否定或他码被确认）、pending（有订单但无验证）、unordered（未下单）、abstained（当时拒答）。客服更正售后原因后，复查结果随之改变；建议记录本身不被改写，新模型上线后历史建议仍带原模型版本与依据。
