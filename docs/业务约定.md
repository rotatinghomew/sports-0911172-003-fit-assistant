# 当前业务约定

height 为厘米、foot 为厘米；测量时间、订单时间和回访观察时间分别保留。没售后记录不代表合身。换货引用原购买和新购买，原记录不删除；correct 保留变更历史。现有可售查询仅返回数量大于零的 SKU，不提供尺码预测。

## 数据与一致性

金额均为整数分；日期使用零补齐的日期或同一时区时间字符串，跨时区输入应由调用方先规范化。所有 ID 为业务编号。写入会增加修订并保留旧值，历史 `recorded_at` 是登记时间，不等于事实发生时间；不能据此推断未观测到的业务事实。

单次业务操作是一个事务，失败不留下中间结果；整份回放按顺序逐项执行，前一项成功不会因为后一项失败而撤销。现有重复编号拒绝语义及已完成状态的重试语义由业务操作维护。操作台 JSON 中 `results` 是操作结果，`state` 为当前业务记录；历史以 `Store.history` 查询，当前状态与历史不能混为一谈。

## 尺码建议

`advisor.recommend` 的合身结论只由证据决定：库存只影响随附的可买清单，不影响合身结论；合适尺码售罄时，结论与可买选择分开返回，可买清单不代表同等合适。证据不足时拒答（`conclusion='abstain'`），不给确定尺码；建议只记录不下单。每条建议持久化保存模型版本、依据、适用人群与不确定处，一经写入不修改，新的判断另开编号；售后更正只影响之后的建议与评估，历史建议仍按当时证据解释。

`orders.place` 的可选 `advice` 字段把订单与建议关联，校验人与款式一致；`advisor.review` 据此把下单时的判断与实际换退对照，状态为 confirmed/contradicted/pending/unordered/abstained，使用当前（含更正）的售后原因。

标签语义：未回访、未退货、未售出都不是合身确认；回访确认（followup/fit）才是确认；换货新单尺码记为"解决尺码"，未经回访确认；退货只记方向；非尺码原因（如 fabric、changed_mind）不作合身证据。分析按业务时间字段（measured_at/happened_at/observed_at/corrected_at）还原各时刻可见信息，不用变更日志的登记时刻。

候选模型的可比较验证见 `scripts/evaluate_advisor.py`：每个请求只用它发生时刻之前可观察的记录，同一人的请求不跨验证折，报告可靠性、拒答覆盖以及体型、品牌、证据积累分层的缺口。设计与口径细节见 `docs/尺码建议.md`。
